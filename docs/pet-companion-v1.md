# 兔朱迪宠物与设备长期记忆 V1

## 范围

首版以 `device_id` 作为唯一主人档案标识，不进行声纹识别。同一台设备上的所有说话者共享一份宠物状态和用户记忆。

数据保存在服务端 SQLite，ESP32 不保存完整档案，也不改变现有 ASR → RAG/LLM → TTS、唤醒词、开口等待或音频超时参数。

## 持久化内容

- 宠物状态：亲密度、心情、精力、连续陪伴天数和最后互动时间。
- 明确用户记忆：称呼和喜好。
- 陪玩进度：游戏类型、阶段、轮数、线索/猜测次数和五分钟截止时间。
- 幂等事件：每个 `turn_id` 只结算一次状态，网络重试不会重复增加亲密度。

完整聊天文本不会写入长期记忆表。普通会话仍只保留当前会话最近三轮上下文。

- “我们的亲密度是多少？”

## 状态规则

- 每个中国标准时间自然日首次互动：连续陪伴天数结算一次，亲密度增加 1，精力最多恢复 10。
- 抚摸：亲密度增加 2，心情变为开心。
- 胡萝卜：亲密度增加 1，精力最多增加 12，心情变为开心。
- 开始陪玩：至少需要 10 点精力；开始和每次有效互动会消耗少量精力。
- 猜对：心情变为兴奋并恢复 7 点精力；三次未猜中或公布答案也会因完成陪伴而恢复 3 点精力，心情变为开心。
- 心情会影响后续行为：开心或兴奋时开局语气更活泼；好奇时自然引导；困倦时回答更轻缓，低精力时不会开始新游戏。普通 LLM 回答也会按当前心情调整语气，但不会主动朗读状态值。
- 所有数值限制在 0 到 100。

宠物数值由确定性程序修改，LLM 只负责普通问答时自然使用少量设备档案，不负责计算或写入数值。

## 陪玩规则

- 普通问答保持原规则：首轮加 3 次追问，共 4 轮。
- 一旦识别到陪玩，当前会话上限扩展为 10 轮；单局状态最多保留 5 分钟。到达任一上限即结算并退出游戏。
- “朱迪猜”：用户每轮说一条线索，共 3 条；朱迪只猜一个角色，用户回答“猜对了”或“不对”。如果不对，用户可以揭晓答案。
- “我来猜”：朱迪随机选择题库角色并依次给出 3 条线索；用户最多猜 3 次，第三次仍不正确时公布答案。
- “不玩了”“退出游戏”或“结束游戏”会立即安全退出。若设备连接中断，只要仍在五分钟内，下次唤醒可以继续当前局。

## 观察接口

监视页面会显示朱迪心情、亲密度和连续陪伴天数。也可以读取：

```text
GET /api/demo/pet/{device_id}
```

接口返回该设备的宠物状态及明确保存的称呼/喜好，用于内部演示验证。
